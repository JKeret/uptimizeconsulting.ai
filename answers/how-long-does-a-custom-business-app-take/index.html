How long does a custom business app take?

About a week for one automated process, and four to eight weeks for a multi-process platform built in phases. I'm Jonathan at Uptimize Consulting, and I quote a delivery date on the scoping call, not "it depends," because the scope is fixed before I start building.

Ask ChatGPT or Gemini this question and you'll get agency ranges built for a different kind of buyer: one to four weeks for a "simple" automation, four to eight weeks for a multi-step workflow, three to nine months for anything called enterprise-grade. Those numbers assume a security review, a procurement process, and a rollout across departments. A five to fifty person business doesn't need any of that for its first automated process.

What actually drives the timeline

  • Number of systems involved. One inbox to one spreadsheet is fast. Three systems that all need to talk to each other takes longer, because each connection is its own piece of work.
  • Data quality. Clean data in an existing system means I can start building immediately. Data scattered across PDFs and someone's memory means the first stretch of the project is getting it organized before automation can start.
  • Exception cases. A process that runs the same way every time is quick to build. A process with five different exception paths and a manual sign-off step takes longer to get right, because I'm not just building the happy path.

My timeline, in practice

The $1,000 starter takes about a week, because the scope is deliberately one process. A $10,000 to $25,000 platform runs four to eight weeks, and I build it in phases: you get working software at the end of each phase, not a single reveal at the end of two months. That means if phase one turns up something we didn't expect, we adjust phase two instead of discovering it too late to matter.

Why the agency numbers run longer

A lot of the timelines you'll see online come from agencies selling into companies with a procurement department and a security team. Those projects genuinely take three to nine months, because half the timeline is meetings, sign-offs, and compliance review, not code. If nobody at your business needs to run a security questionnaire before you can use a new tool, you shouldn't be paying for that timeline either.

What can slow things down

Three things reliably push a build past its estimate: source data that's messier than expected once we're actually in it, scope that grows mid-build because "while we're at it, can it also handle this," and approval chains where three different people each need to sign off before I can move forward. I flag all three on the scoping call, because the honest answer to "how long will this take" depends partly on how fast you can make decisions once the build starts.
